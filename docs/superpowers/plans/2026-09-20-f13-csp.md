# F13 content security policy implementation plan

Goal: make the existing CSP safely enforceable, with fresh trusted script nonces, explicit provider origins, actionable privacy-safe reporting and isolated SCORM framing. User authorization: implement the F13 audit remediation; no separate design approval is needed for its stated scope.

Architecture: shared pure policy builder; per-request web proxy nonces passed to Next's request CSP and the root theme script; separate API and SCORM policies; existing public-route rate limiting on a bounded report collector. Keep the existing explicit `CSP_ENFORCE=1` rollout switch until actual protected journeys are verified. Never grant a nonce to tenant-authored marketing snippets, broadly trust all HTTPS origins, or add production unsafe-eval/unsafe-inline script permissions. Explicit script origins preserve dynamic checkout/approved tracking without strict-dynamic transitively trusting arbitrary script URLs recreated from tenant snippets.

1. Inventory browser network providers, installed Next nonce requirements and response-header precedence. Document required deployment origins and unsupported legacy snippets.
2. Write failing policy/proxy/theme tests; implement fresh cryptographic nonces, spoofed-header removal, dynamic root rendering and private/no-store HTML policy. Preserve F11 forwarding behavior.
3. Add exact configured origins for Supabase, Sentry, PostHog, storage and optional integrations, with known video/checkout origins. Reject malformed/wildcard/injected configuration. Keep local dev eval/WebSocket exceptions out of production. Ensure API JSON does not impose the web document policy on SCORM.
4. Implement a separate rate-limited CSP reporting endpoint with size/count/schema limits and no raw URL paths, query strings, script samples or supplied original policies in logs. Cover legacy and Reporting API envelopes.
5. Verify opaque SCORM sandbox headers and same-origin framing without global DENY conflicts. Preserve camera/microphone for same-origin proctoring.
6. Run focused and broader checks and real browser nonce/injection verification where available. Record which authenticated/live-provider journeys remain blocked by F11 infrastructure. Update SEC-01 and the audit honestly; do not equate report-only with enforcement.
