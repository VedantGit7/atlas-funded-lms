## Important findings and deployment behavior

The old API trust boundary could accept a directly supplied forwarding address. The new boundary treats the web service's existing credential as transport authentication and carries a separate request-source marker. A browser rewrite with missing IP cannot impersonate an internal server fetch. Unknown deployed public requests receive retryable 503 before consuming another user's shared unknown bucket. The default trusted proxy count is now zero; copying the environment template does not establish trust. Missing web attribution fails deployment validation.

This is a coordinated rollout: old web callers do not send the new source/IP context and will receive 503 from the new API. Deploy compatible versions together, or the new web first after verifying its edge configuration. External provider callbacks must enter through the verified web path. Keep the proxy credential out of provider configuration. Local tests cannot establish that a production edge overwrites headers or that an origin is unreachable directly.

The SCORM browser diagnostic uses the application's production sandbox headers with fixture-only cookies. The initial iframe navigation receives a SameSite=Lax cookie, but a relative package script request is cross-site and omits it. The package cannot read parent DOM, cookies or localStorage. Therefore a new asset path and `postMessage` handler alone would still be broken. A safe design needs a dedicated, short-lived read capability scoped to tenant, membership, module and immutable package version; active access must be rechecked, with explicit key, lifetime, renewal, revocation and log-redaction rules. Initialization, saved state, bounded messages and both claimed SCORM versions then require browser acceptance. No new capability or broader framing permission was introduced in this pass.

The retention fix improves failure visibility, not erasure coverage. Proctoring media still uses the currently configured bucket/provider rather than persisted original storage identity and does not confirm absence before removing a successful row. Some retention tasks still exclude inactive tenants, metadata-retention enforcement is incomplete, and no authoritative legal-hold system exists. Access removal and partial exports remain explicitly described as such.
