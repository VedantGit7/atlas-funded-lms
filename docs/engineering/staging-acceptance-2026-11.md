## Found and fixed

1. **Approved courses showed learners no lessons** (launch blocker). Nothing published modules and lessons. Fixed in #263: approval publishes them, and migration 130 backfills courses approved before.
2. **An open lesson saved progress every ~1.75 s,** with a made-up position. Fixed in #264, which also marks an opened lesson in progress from 0%.
3. **Device session capture refused every non-admin.** Fixed in #264.

## Found, not fixed yet

- **`TENANT_BASE_DOMAIN` isn't set on staging,** so a new tenant's built-in address is `<slug>.localhost.test`. Only matters when other schools are added (launch plan, "Later: if other schools are added").
- **Signing up with Google didn't make the person a learner** (launch blocker for Google sign-up). The Google callback skipped the self-service learner membership that password sign-in creates. Better Auth still made a session row, but the web doesn't pass its cookie on after a refusal, so the person isn't signed in, and the message was generic. Fixed on branch `fix/google-signup-learner-membership`: every sign-in path shares one step (`resolveSignInMembership`), and a real refusal says "You don't have access to this academy yet".
- **The sign-in page shows "Continue with Google" even when no Google client is configured,** and it only leads back to an error. Staging now has its client. The product could hide the button when there is none.
- **Staging's academy branding is the placeholder:** the sign-in page shows "Your Academy" (initials "YO") beside "New to FundedBeyond?". Set the branding (logo, name, colours) in Admin → Branding before launch; it's content, not code.
- **Platform routes validate input before checking the caller is an operator** (`create-platform-route.ts`). A non-operator, or an anonymous caller, gets 400 "Platform reason is required." or a query validation error before the 403. No data leaks, but it shows the API's expected inputs. Hardening: resolve the principal before reading the reason, query and body.
- **The tenant host checks authentication before the Origin check,** unlike the platform host. The signed-in path is covered by the unit test and two browser layers (see the table), not shown live.
