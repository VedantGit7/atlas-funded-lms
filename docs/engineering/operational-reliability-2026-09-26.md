## Corrections made

- Restore previously reused a fixed scratch name and tolerated some restore errors. It now requires explicit source/user/quiescence, generates a unique target, refuses collisions, strictly fails restore errors, checks content beyond counts, and requires verified cleanup. Marker mismatch never triggers a drop.
- Review found that `pg_sequences.last_value` hides the state of uncalled sequences. Verification now reads actual `last_value` and `is_called` without advancing the sequence. A regression reproduces the earlier false success.
- Empty application datasets no longer satisfy the drill. The scheduled CI job now seeds guarded synthetic tenant data first. Batching table snapshots reduced Docker startup overhead while preserving per-table comparisons.
- Rollback preflight no longer passes without an identity. Optional health observation requires different candidate and rollback identities. It expressly reports that no deployment was performed.
- Restore application validation no longer interpolates a URL through a shell or runs unrelated database tests. It requires an expected release, bounds HTTP checks, redacts provider output, and reports health-only evidence.
- Added repeatable failure/process-loss drills, migration provenance/catalog verification, ordinary CI tooling tests, and corrected release/rollback/observability runbooks.

## Open work before operational sign-off

1. **Managed recovery:** restore the actual database provider's backup into isolated staging; validate database/cluster configuration, representative domain data, tenant access, storage/Auth dependencies, measured recovery point and complete application downtime.
2. **Hosted rollback and restarts:** deploy identifiable immutable artifacts, switch to the previous compatible artifact, verify API/web/worker behavior and job completion. Prove host replacement of an unhealthy but still-running instance; Compose's `restart: unless-stopped` alone does not do this.
3. **Real alerts:** configure the selected monitor and recipient, reconcile heartbeat grace/severity timings, then capture authorized incident, delivery, acknowledgement and recovery records. Local 204 receipts do not close this.
4. **Live storage and scale:** test R2 signing/CORS/expiry, full-size upload, real deletion failure/retry, worker resource limits, worst expanded archive and concurrent/soak workloads.
5. **SCORM cleanup:** implement reference-aware garbage collection for abandoned/superseded attempt prefixes. The drill confirmed an orphan remains. Do not delete published packages using a blanket age rule. Test active-reference protection, tenant boundaries, interrupted deletion and retry.
6. **Migration provenance:** retain the explicit history gap. No current catalog repair is needed for these 37 tables. Recover trustworthy historical evidence or obtain a documented provenance exception/replacement-database plan; do not manufacture checksums. The 083 historical data backfill cannot be proved because no eligible historical rows remain.

These are remaining acceptance/implementation requirements, not newly accepted risks. Existing exception owners and expiry dates are unchanged.
